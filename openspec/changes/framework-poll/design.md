## Context

這是一個全新的前端專案，目標是建立一個互動式計分板讓使用者快速投票登記使用的框架。專案採用單頁應用架構，不使用路由系統，所有狀態管理透過 Zustand，資料持久化使用瀏覽器端的 IndexedDB。

**當前狀態：**
- 全新專案，無現有程式碼
- 目標部署環境：靜態網站託管（無後端）
- 使用者類型：路過訪客（一般使用者）+ 管理員

**約束條件：**
- 純前端應用，無後端 API
- 管理員密鑰存於環境變數，僅用於前端功能鎖定（非安全機制）
- 資料僅存於使用者瀏覽器本機端

## Goals / Non-Goals

**Goals:**

- 建立直覺的視覺化投票介面，降低參與門檻
- 實作完整的版塊管理功能（CRUD）
- 使用相對座標系統支援圓點自由佈局
- 提供資料匯出功能（CSV 格式）
- 實作軟刪除機制保留歷史資料
- 響應式設計支援桌機、平板、手機

**Non-Goals:**

- 不實作多使用者同步功能
- 不提供雲端儲存或跨裝置同步
- 不實作真正的身份驗證系統
- 不支援即時協作或衝突解決
- 不提供資料分析或視覺化圖表

## Decisions

### 使用 IndexedDB 而非 localStorage

**決策：** 採用 IndexedDB 作為資料儲存方案

**理由：**
- localStorage 有 5-10MB 容量限制，IndexedDB 可儲存更多資料
- IndexedDB 支援索引查詢，效能更好（特別是 `[categoryId, isDeleted]` 複合索引）
- 支援事務操作，資料一致性更佳
- 未來若需要大量資料時更容易擴展

**替代方案考慮：**
- localStorage：實作簡單但容量有限，查詢效能差
- Web SQL：已廢棄標準，不考慮

### 採用相對座標系統

**決策：** 圓點位置使用 0~1 相對座標（xRatio, yRatio）

**理由：**
- 響應式設計時，版塊大小會改變，相對座標能維持圓點的相對位置
- 不同裝置螢幕尺寸差異大，絕對座標會導致佈局錯亂
- 計算簡單，點擊位置轉換公式：`xRatio = clickX / containerWidth`

**替代方案考慮：**
- 絕對像素座標：會在不同螢幕尺寸下失效
- Grid 系統：限制太多，無法自由放置

### 軟刪除機制

**決策：** 所有刪除操作採用軟刪除，保留 `deletedAt` 欄位

**理由：**
- 保留歷史資料供 CSV 匯出使用
- 未來可能需要恢復誤刪資料
- 符合資料審計需求
- 對效能影響小（透過 `isDeleted` 索引過濾，`deletedAt` 專注保存刪除時間）

**替代方案考慮：**
- 硬刪除：資料無法恢復，不符合需求
- 保留完整版本歷史：過於複雜，超出當前需求

### Zustand 作為狀態管理

**決策：** 使用 Zustand 管理應用程式狀態

**理由：**
- 輕量級（~1KB），學習曲線低
- API 簡潔直觀，不需要 Provider 包裹
- TypeScript 支援良好
- 效能優異，不需要額外最佳化

**替代方案考慮：**
- Redux：過於複雜，boilerplate 太多
- Context API：效能較差，重新渲染問題
- Jotai/Recoil：原子化狀態過於零散

### shadcn/ui 元件庫

**決策：** 使用 shadcn/ui 作為 UI 元件基礎

**理由：**
- 元件直接複製到專案，完全可控
- 基於 Radix UI，無障礙支援完善
- Tailwind CSS 整合良好
- 無額外 bundle size 負擔

**替代方案考慮：**
- Material UI：bundle size 大，客製化困難
- Ant Design：設計風格固定，不易調整
- Headless UI：需要自行處理樣式

### 管理員密鑰策略

**決策：** 密鑰存於 `.env` 的 `VITE_ADMIN_SECRET`，前端直接比對

**理由：**
- 純前端應用，無後端驗證
- 目的是防誤操作，不是真正安全機制
- 使用環境變數避免 hardcode
- 符合專案簡單部署需求

**風險認知：**
- 密鑰可從打包後的 JavaScript 中提取
- 不適合真正需要安全保護的場景
- 適用於內部工具或低安全需求場景

### 程式碼品質工具

**決策：** 使用 ESLint + Prettier + Husky 進行程式碼品質與格式化管理

**理由：**
- ESLint 提供 TypeScript 與 React 規則檢查
- Prettier 確保程式碼風格一致性
- Husky + lint-staged 在 pre-commit 階段執行檢查，防止錯誤提交
- 確保 React Compiler 能正確最佳化程式碼
- 預先偵測潛在錯誤，提升程式碼品質
- 整合 @typescript-eslint、eslint-plugin-react-hooks

**設定重點：**
- 使用 @typescript-eslint/recommended 規則集
- 啟用 React Hooks 規則檢查
- Prettier 與 ESLint 整合避免格式衝突
- 支援 Vite 專案結構
- pre-commit hook 只檢查 staged 檔案（效能最佳化）

**Git Hooks 設定：**
- pre-commit: 執行 lint-staged（ESLint + Prettier）
- 不執行測試套件（保持提交速度）
- 可使用 --no-verify 跳過（WIP commits）

**替代方案考慮：**
- 僅使用 TypeScript：無法檢查 React 特定問題
- 僅使用 Prettier：缺少程式碼品質檢查
- 不使用 Git hooks：依賴手動執行，容易遺漏

### 使用 React Compiler 進行自動效能最佳化

**決策：** 整合 React Compiler 進行編譯時自動最佳化

**理由：**
- 自動 memoization，無需手動使用 useMemo、useCallback、React.memo
- 大量圓點渲染時減少不必要的重新渲染，提升效能
- 與 Zustand 狀態管理整合良好，自動最佳化訂閱元件
- 響應式佈局時自動最佳化 resize 事件處理
- React 19 官方推薦工具，穩定版本 (v1.0)

**效能預期：**
- 減少 20-40% 不必要的重新渲染
- 降低記憶體使用量
- 改善互動回應速度，特別是大量圓點場景

**整合方式：**
- 使用 babel-plugin-react-compiler 與 vite-plugin-babel
- ESLint 整合透過 eslint-plugin-react-hooks@latest
- 編譯時最佳化，無執行時開銷

**替代方案考慮：**
- 手動最佳化：需要大量 useMemo/useCallback，容易遺漏且維護成本高
- 不做最佳化：大量圓點渲染時效能可能不足

### 資料模型正規化

**決策：** Category 和 Dot 分開儲存，透過 `categoryId` 關聯

**理由：**
- 查詢效能更好（索引最佳化）
- 刪除 Category 時可批次處理 Dots
- 資料一致性更易維護
- 符合關聯式資料庫設計原則

**替代方案考慮：**
- 巢狀結構（Category 包含 Dots 陣列）：查詢效率低，更新複雜

## Risks / Trade-offs

### [風險] 前端密鑰可被提取

**說明：** 管理員密鑰打包在前端程式碼中，可透過瀏覽器開發者工具或反編譯提取

**緩解措施：**
- 在文件中明確標示這不是安全機制
- 適用場景為內部工具或信任環境
- 若需真正安全，建議改用後端驗證

### [風險] IndexedDB 資料可能遺失

**說明：** 瀏覽器清除資料、隱私模式、儲存空間不足都可能導致資料遺失

**緩解措施：**
- 提供 CSV 匯出功能定期備份
- 在 UI 提示使用者定期匯出資料
- 未來可考慮加入匯入功能

### [權衡] 無跨裝置同步

**說明：** 資料僅存於本機端瀏覽器，無法跨裝置存取

**理由：** 純前端架構決策，加入同步功能需要後端支援

**影響：** 使用者更換裝置或瀏覽器需要重新建立資料

### [權衡] 圓點重疊時辨識度降低

**說明：** 當多個圓點位置接近時，可能難以點擊或辨識

**緩解措施：**
- 使用 opacity: 0.8 半透明效果
- 加入明顯邊框
- hover 時顯示名稱
- 未來可考慮加入自動分散演算法

### [風險] 大量資料時效能問題

**說明：** 當圓點數量超過數千個時，渲染效能可能下降

**緩解措施：**
- 使用 IndexedDB 索引最佳化查詢
- 只渲染未刪除的圓點
- 未來可考慮虛擬化或分頁

## Migration Plan

**初始部署：**
1. 建置專案：`pnpm run build`
2. 設定環境變數 `VITE_ADMIN_SECRET`
3. 部署靜態檔案至託管服務（Vercel / Netlify / GitHub Pages）
4. 驗證管理員密鑰功能正常

**Rollback 策略：**
- 純前端應用，無資料庫遷移問題
- 直接部署上一版本即可
- 使用者資料存於本機端，不受部署影響
